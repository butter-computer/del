# 0.1.46 source update

Main and Side chats now show provider-authored progress checklists. Pending tasks
have circles, active work has an animated ring, completed tasks have checkmarks,
and cancelled tasks have dashes. Changes fade briefly and completion morphs the
marker into a check. Reduced Motion uses a static presentation.

The checklist appears only after structured provider data arrives. It remains
readable beside collapsed tool history, wraps in narrow Side chats, and survives
reopening the conversation. Later turns continue the list in a new card without
rewriting earlier progress. Ending, interrupting, or failing a response does not
complete unfinished tasks.

Codex, Claude, and OpenCode task tools are enabled only in Del's provider threads
or processes. Existing user configuration files are untouched. Claude's live
stream and native saved-history result formats are both supported. Failed task
mutations do not change the displayed progress.

See [provider progress checklists](../provider-progress.md) for contracts, source
references, persistence details, and the separate scripted visual-preview mode.

Validation includes real Codex plan updates, recorded live and saved Claude task
results, real OpenCode todo updates, and a process-local OpenCode configuration
test. Automated tests cover replay, interrupted tasks, provider boundaries,
clearing, narrow layout, Side chat isolation, and Side snapshot persistence.

The final automated run passed 682 tests (44 environment-dependent tests ignored),
and the locked app build succeeded. Separate native checks passed for all three
providers and OpenCode configuration isolation.
