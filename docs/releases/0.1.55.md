# Del 0.1.55

Session-owned servers and process controls, plus the improvements published in
source updates since the previous downloadable release, 0.1.25.

- **This session** shows commands and servers belonging to the selected session,
  including its Side chats and sidebar terminals. **All sessions** includes the
  other sessions and shared project terminals. Shell wrappers, provider hosts,
  Del housekeeping and known REPL helpers stay out of the counts.
- Claude, Codex and OpenCode commands carry a local launch marker. This preserves
  ownership for detached servers and separates commands launched through Codex's
  shared app-server without guessing from their working directory.
- Hover a row, or focus its trailing control with the keyboard, to reveal **Stop
  process**. Stop targets that command and its descendants, gives them two seconds
  to exit, and force-stops survivors. Every signal checks the process birth time;
  it never signals a provider's shared process group.
- Process menus refresh every two seconds while active, including while open.
  Server rows show listening localhost ports and show **Stopping…** during shutdown.
- Includes the intervening source updates: provider progress checklists, Side
  history and slash commands, historical commit reviews, session persistence,
  explicit Quit/background behavior, and the 0.1.53 interface polish. The 0.1.54
  fixes preserve deferred attachment sends, prevent deleted queues from returning,
  and retain complete tool output in bounded scrolling details.

Ownership markers last for the current Del launch. Older untagged shared commands
with unverifiable ownership appear only in All sessions. A command that removes
its marker and detaches before observation cannot be attributed. Process arguments
and unrelated environment values are never displayed, logged or persisted.

## Download

Install **Del-0.1.55-arm64.dmg** on an Apple Silicon Mac running macOS 11 or later.
The release includes a SHA-256 checksum and `latest.json` for the in-app updater.
The public app uses `computer.butter.del`, is ad-hoc signed, and is not notarized.
Provider CLIs and their authentication remain separate. Local development builds
keep their existing signing identity.

See the [validation record](https://github.com/butter-computer/del/blob/v0.1.55/docs/releases/0.1.55-validation.md),
[0.1.54 reliability notes](https://github.com/butter-computer/del/blob/v0.1.55/docs/releases/0.1.54.md),
