# 0.1.44 source update

Slash suggestions now open at a word boundary anywhere in the composer, including
after existing prompt text and on later lines. For example, `please check this /`
opens the same skill and command menu as a leading `/`. Filtering works while
editing a slash word in the middle of a longer prompt.

All available command kinds remain visible regardless of position. Selecting a
completion replaces only the active slash word, preserving surrounding text and
existing skill tokens. Selected skills keep their exact provider identities
through draft and queued-message restoration. Existing standalone command dispatch
rules remain unchanged; ordinary prose containing a slash does not execute a control.

Validation: the screenshot's input reproduced the missing-menu bug in a failing
regression test. All nine command-menu tests pass, including a GPUI test of actual
menu filtering and skill/action insertion with text on both sides of the cursor.
The native app build, formatting, version consistency, and diff checks pass. The
local app was installed with its existing signing identity.
