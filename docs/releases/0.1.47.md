# 0.1.47 source update

Skills and commands begin loading as soon as a main or Side composer receives its
provider, account, and project. Opening `/` reuses the ready catalog, including
when returning to a previously used context. After one minute, the next query
refreshes it in the background while existing suggestions stay visible. Failed
refreshes keep the last successful list and can retry after five seconds. A cold
provider may still show loading if the menu opens before its first discovery
finishes. Catalogs are held in memory and scoped to provider, account, and folder.

The Space picker now uses a balanced check with rounded strokes. The composer no
longer duplicates the project folder icon and label; the footer retains project
context and new sessions keep their folder selector. Recent commit history has
one header row: “Recent commits” on the left and “N total” on the right. Individual
commit line counts remain; aggregate header line counts are removed.

Regression coverage checks preload before typing in both main and Side chats,
ready-menu reuse, and retaining suggestions during a stale refresh. Existing Side
coverage also verifies account isolation, skill insertion, and command behavior.

Validation: 442 app tests passed (14 environment-dependent tests ignored). The
locked signed macOS build succeeded. On-screen checks confirmed preloaded main
and Side slash suggestions, the new selection check, the simplified composer,
and the one-row commit header.
