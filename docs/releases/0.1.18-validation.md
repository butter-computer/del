# Del 0.1.18 validation

## Automated checks

- `cargo test --locked --workspace`: 550 passed, 0 failed, 42 opt-in tests ignored.
  Includes 67 agent tests and 284 app tests.
- `cargo clippy --locked --workspace --all-targets -- -D warnings`: passed.
- `cargo fmt --all -- --check` and `git diff --check`: passed.
- Signed local debug bundle built with `scripts/bundle-macos.sh debug`, using
  Xcode and `MACOSX_DEPLOYMENT_TARGET=11.0`.

Coverage includes project boundaries, authenticated sender identity, idempotent
requests/replies, cyclic exchanges, context pagination, peer priority, original
work retention, failed/uncertain delivery recovery, Side chat alias rebinding,
and exact provider-envelope reconciliation. ACP fixtures verify HTTP/stdio MCP
configuration and credential lifecycle. GPUI tests cover peer navigation and
preserving a Side chat's mailbox when disposing its saved view.

## Live verification during development

- An opt-in two-Codex test read recorded context, exchanged a request and reply,
  and explicitly completed original work using isolated temporary metadata.
- Main-chat / Side-chat requests and replies were checked in Del, including
  activity indicators, unread dots, navigation ticks, and clickable peer links.
- Delivered receipts and completed work survived two app restarts; a restored
  Side chat's native ID rebound to its existing mailbox without replaying requests.
- Two separate top-level sessions in one project exchanged an actual request and
  reply: “Isolated Del cross-session demo” asked READY for its marker and received
  `PEER_UI_COBALT_1030`. Both receipts were delivered.
- Visually checked centered provider-logo/name exchange rows, expanded tool
  output alignment, and the final icon-free tool headers in the running app.

Native Claude and OpenCode exchanges were not exercised live; their shared
project/identity behavior is covered by the manager and MCP bridge tests. Terminal
delivery is cooperative and does not manage a CLI's native user-input queue.
Desktop capture was intermittently stale during earlier restart checks; restored
accessibility state and lifecycle regression tests supplied additional evidence.

The Rust `block 0.1.6` dependency still emits its existing future-incompatibility
notice. It does not fail the current build or strict Clippy checks.

This is a source update and signed local build, not a new public installer release.
