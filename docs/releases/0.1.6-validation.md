## Additional integration checks

The ignored live tests were run separately, with isolated temporary application
data and OpenCode XDG directories. These results supplement the default suite;
the default suite's 36 ignored tests must not be interpreted as passing.

- Codex: 11 live tests passed, covering streaming, model discovery, approvals and
  file changes, interruption/steering, title generation, goal execution and
  pause/resume/clear/restore, and isolated missing-login/API-key cases. The test
  requiring a supplied saved thread ID was not run. The app's real Codex
  follow-up/steering/stop test passed on an isolated rerun after its initial
  latency timeout.
- OpenCode: command completion, model reset/plan transitions, forms and
  cancellation, title generation without history mutation, UUID account
  switching, follow-up/steering/stop, exact terminal resume, and terminal tab
  isolation passed. Both cold and warmed live chat browser bridge tests passed.
- Real PTY programs: all four tests passed for Vim, top resize, Claude rendering
  and input, and Codex rendering and input. Rendering tests do not establish
  successful provider authentication.
- Native WebKit: navigation, JavaScript, screenshots, isolated profiles,
  persistence, deletion, and cookies/storage across process restart passed.
- Native PDF/DOCX preview lifecycle and simulated dictation lifecycle passed.
  Microphone capture was not exercised.
- macOS signing and installation harnesses passed: builds retain identity,
  different keys and incomplete identities are rejected, running-app replacement
  preserves identity, and retired bundles are cleaned up.
- Public release download/staging, checksum/signature validation, and tamper
  rejection passed against the existing published 0.1.5 release.

Installed provider versions were Codex 0.165.0, Claude 2.1.312, and OpenCode 2.1.4.

## App smoke checks and limitations

The final local bundle launched and displayed v0.1.6. A real Codex chat submitted
through the app returned exactly `DEL_CODEX_016_OK`, verified in its persisted
Codex response; Del persisted the session as idle. Keyboard navigation opened
Settings and the utility panel, with Files, Changes, Terminal, and Browser
controls present in the accessibility tree. Earlier mock chat and conversation
search checks passed.

After the Mac was unlocked, desktop automation still returned stale screenshots
and coordinate input failed with `noWindowsAvailable`. Therefore a complete
manual pass through themes, file editing, changes, terminal output, and browser
interaction is **not established**. The native and automated tests above provide
coverage, but do not replace those missing manual checks.

Claude inference checks failed because the CLI reported an expired OAuth session
that could not be refreshed. At the user's request, live testing continued with
Codex instead; Claude inference and Claude goal/MCP behavior remain unverified.

**Known failing live check:**
`terminal_host::opencode_tests::real_opencode_terminal_mcp_status_and_question`
timed out on both attempts. The terminal model reported that the Del MCP tools
were unavailable; no status/question round trip reached the mock host. This
remains unresolved. It is distinct from the passing OpenCode chat browser bridge
and ordinary terminal launch/resume tests. The test now includes its terminal
screen in the failure message to make follow-up diagnosis actionable.
