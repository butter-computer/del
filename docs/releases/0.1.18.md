# Del 0.1.18

Sessions in a Del project can now communicate as equal peers across providers.
There is no required orchestrator: ask an agent to read another conversation's
recorded context, request information or changes, and receive its reply.

- Adds authenticated project-scoped discovery, paginated public context reads,
  durable requests/replies, and explicit work controls through Del's MCP tools.
  Sibling worktrees share their configured project; unrelated projects stay separate.
- Del delivers peer messages before queued user messages at a safe input boundary.
  Responding to a peer or ending a model turn does not finish the original task.
  Queued user input waits until that work explicitly completes.
- Persists delivery receipts, idempotency keys, work state, and restored Side chat
  routing. Uncertain deliveries require review before retrying. Closing a saved
  Side chat backend preserves its mailbox; explicit deletion cancels exchanges.
- Gives each Codex, Claude, OpenCode, and ACP chat its own authenticated identity.
  Receiving a request preserves its provider/account and permissions. Terminal
  agents have a cooperative inbox; Del does not control native CLI user queues.
- Shows centered, clickable `Current agent ⇄ Other agent` exchange rows with
  provider logos. Peer work appears in navigation ticks, activity indicators,
  unread dots, and session-tab retention. Recovery actions live in the context menu.
- Removes leading tool-call icons and nested indentation. Expanded calls and
  output align with the chat text while retaining disclosure and animation.

See [project peer sessions](../peer-sessions.md) for details and
[validation](0.1.18-validation.md) for tested paths and limitations.

This updates source and the local build. No new downloadable GitHub installer
is published with this commit.
